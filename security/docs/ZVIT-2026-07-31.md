## 2. Поточний стан захисту

### 5 шарів безпеки

```
Layer 1  — macOS Firewall ON + Stealth (mac-mini)
Layer 2  — SSH: keys only, root locked, PasswordAuthentication no (vuzol)
Layer 3  — iptables DOCKER-USER: DROP all, ACCEPT 22/80/443 (vuzol)
Layer 4  — Tailscale ACL: mac-mini ↔ vuzol, default deny
Layer 5  — Tailnet Lock: ENABLED, mac-mini + vuzol signed
```

### 6 поверхонь атак — статус

| Поверхня | Доступ | Захист |
|----------|--------|--------|
| mac-mini (публічний IP) | Невидимий | Firewall + Stealth |
| vuzol :22 SSH | Публічний | Keys only, root locked |
| vuzol :80/443 | Публічний | nginx, /api/ → basic auth |
| vuzol :8000 Task API | Tailscale only | HTTP (без auth всередині mesh) |
| vuzol Docker контейнери | Tailscale only | DOCKER-USER DROP для публічного |
| Tailscale mesh | Криптографічно | ACL + Tailnet Lock |

### Сервіси

|--------|--------|----------|
| ssh | active | keys only |

## 8. Уніфікація завдань (2026-07-31, друга половина)

### Проблема
Три незалежні сховища завдань, які розходились:
1. `~/spaces/tasks-all.json` (mac, tasks-parse.py з файлів)
2. `~/.claude/projects/*.json` (mac↔vuzol, state.py scp sync)
3. PostgreSQL `orchestrator` (vuzol, state3.py + Task API)

TG бот читав з PostgreSQL, а оновлення вносились у файли. Дані не збігались.

### Рішення: files-first, DB-cache

**Принцип:** файли — єдине джерело правди. PostgreSQL — read-only кеш.

**Sync pipeline:**
```
_infra/projects/*.json → ~/.claude/projects/ → scp vuzol → state3.py migrate → PostgreSQL
```
